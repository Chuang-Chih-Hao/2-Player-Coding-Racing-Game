# 雙人程式賽車：極速工程師 🏎️🧩

為兩位國中一年級學生及一名線上老師設計的繁體中文 Scratch 風格積木賽車。教師建立房間，學生利用 Google Blockly 彩色積木編輯賽車規則，再用鍵盤控制同一場伺服器同步的俯視角競速。

**學生學的是拖曳、拼接的圖像化 Scratch 風格積木，不需要閱讀或輸入 JavaScript。** JavaScript 僅作為程式實作技術。Blockly 轉成有限種類的 AST（抽象語法樹），由伺服器安全解譯器執行，並非任意 JS 執行。

## 課程與學習目標

- **變數**：最高速度、加速度、轉向、煞車、目標速度會真實影響物理。速度高不代表起跑快，也更可能衝出彎道。
- **條件判斷**：使用 C 型「如果……那麼……否則……」積木，插入六角形條件，做出不同賽車決策。
- **事件觸發**：比賽開始、進彎、離彎、障礙物、道具、加速區、按鍵與終點事件真正執行下方積木。
- **除錯與分析**：看到最近執行的積木、條件判斷結果與即時車輛反應，賽後對照回合紀錄。

| 第一節 40 分鐘 | 活動 |
| --- | --- |
| 0–5 | 老師建房、學生加入、熟悉操作 |
| 5–15 | 第一場比賽、最高速度變數 |
| 15–25 | 加速度變數調校與測試 |
| 25–35 | 進入彎道的 if / else |
| 35–40 | 比較成績與積木差異 |

**休息 10 分鐘**：可暫停課程，不必切換房間。

| 第二節 40 分鐘 | 活動 |
| --- | --- |
| 0–10 | 認識事件帽子積木 |
| 10–20 | 取得道具與按鍵觸發 |
| 20–30 | 自由程式挑戰 |
| 30–35 | 最終雙人競速 |
| 35–40 | 成績、學習歷程與回饋 |

老師自由切換主題，系統不會強制按時間切回合。

## 學生：加入與操作教學

1. 開啟遊戲，選擇「我是學生」，輸入暱稱和教師提供的六位房間代碼；或開啟教師分享的邀請連結。
2. 由工作區的「事件、變數、控制、偵測、道具」分類選取彩色方塊，以滑鼠拖曳、拼接與拆開。
3. 先放黃色「當……時」事件帽子，再把橘色動作方塊拼到下方；條件必須使用綠色六角形偵測積木，放入 C 型「如果」條件槽。動作可接到「那麼」與「否則」兩側。
4. 點擊數字欄位或下拉選單修改；垃圾桶刪除、工作區縮放、復原／重做、清空和恢復預設都可用。預設積木依本課題整理，不相關事件先收合以避免重疊；可點「整理積木」重排，點「⛶ 放大積木」切換大型 Blockly 工作區，按 Esc 也能退出。
5. 點「練習測試」，用方向鍵觀察程式如何真的改變賽車；若車輛開太遠或撞到路障，點「↻ 重新練習」就會立即回起點，保留目前積木設定，不用慢慢開回去。確認後點「鎖定積木／準備」。
6. 老師按「開始倒數競速」後，與另一名學生同時在同一條賽道競速。若卡住，可按「🙋 舉手求助」通知老師。右下角「積木執行訊息」是可展開的除錯與提示紀錄，**不用在這裡輸入程式碼**。賽道橘色禁行標誌是路障、黃色方塊是道具、青色線段是加速區。

**駕駛控制**：↑／W 加速、↓／S 煞車、←／A 左轉、→／D 右轉、空白鍵使用道具；Shift 和 E 也可作為積木按鍵事件。

### 積木種類與數值

| 類型 | 範例 | 實際作用 |
| --- | --- | --- |
| 橘色變數 | 將最高速度設為〔70–230〕 | 調整真正的車輛最高速度 |
| 橘色變數 | 將加速度設為〔3–16〕 | 調整加速率 |
| 橘色變數 | 將轉向靈敏度設為〔1–6〕 | 左右轉向效率與穩定性 |
| 橘色變數 | 將煞車強度設為〔2–12〕 | 減速能力 |
| 橘色變數 | 將目標速度設為〔35–230〕 | 自動限制動力的上限，可用來過彎減速 |
| 橘色變數 | 將速度改變〔-40～40〕 | 對當下速度做一次變更 |
| 金色控制 | 如果＜條件＞那麼／否則 | 根據實際車況走不同分支 |
| 綠色偵測 | 彎道、速度大於、障礙物、距離障礙物、有道具、道具種類 | 判斷真偽 |
| 黃色事件 | 比賽開始、起跑線、進／出彎、碰撞、拾取、加速區、按鍵、終點 | 發生時執行連接的方塊 |
| 紫色道具 | 啟動道具、播放音效 | 使用所持道具或發出提示 |

**速度限制的關係**：平常的速度上限是「最高速度」與「目標速度」的較小者。預設直線目標速度是 230，因此改最高速度積木能直接改變直線表現。進入彎道可利用事件把目標速度改低，離開後調回 230。

### 五回合學習主題

| 回合 | 任務限制 |
| --- | --- |
| 01 最高速度 | 僅能改預設最高速度積木的數值 |
| 02 加速度 | 僅能改預設加速度積木的數值 |
| 03 彎道 if / else | 僅能修改「當進入彎道時」事件內的邏輯 |
| 04 道具事件 | 僅能修改「取得道具」及「按下按鍵」事件 |
| 05 自由挑戰 | 可自由新增、刪除與重排合法積木 |

除了工作區可用分類，**伺服器也驗證任務限制**，避免學生修改了其他主題的積木而失去教學比較效果。

## 賽道、道具與比賽規則

三張賽道：**新手練習賽道**（變數）、**彎道技術賽道**（判斷）、**道具競速賽道**（事件）。

每張賽道有起終點、障礙物、拾取點和加速區。離開路面會減速；碰撞使速度降低。通過賽道中段檢查點後才能正確計下一圈，避免在起點來回刷圈。預設 2 圈，可設定 1～5 圈；雙方完成或超過 200 秒自動結束，老師亦可提前結束。

道具效果：**氮氣**短時間提高速度上限；**防護盾**短時間免除撞擊減速；**抓地力強化**改善操控與離路減速；**干擾器**短時間影響對手轉向。道具可透過「當按下空白鍵」事件接「如果有道具」和「啟動道具」積木執行。

伺服器每 50 毫秒演算物理與事件，廣播車輛座標、方向、圈數、速度、碰撞、道具；瀏覽器做平滑顯示。勝負應結合駕駛技術和程式策略，不保證全部變數調到最高最優。

## 教師控制台操作

1. 點「我是老師」→「建立教師房間」，取得六位房間代碼。複製邀請網址傳給兩位學生。
2. 設定學習主題、賽道、圈數、難度，按「套用」。兩名學生各有專屬積木工作區，老師可選 A 或 B 查看實際通過驗證的積木。
3. 學生按「請老師協助」後，控制台會顯示姓名、連線、準備／求助狀態、最近的錯誤、嘗試及積木。老師可發送文字提示、協助修改數值積木、恢復指定學生預設、停止其練習。
4. 老師控制正式賽車的開始、暫停、繼續、新回合、提前結束及卡車救援。已加入學生需鎖定積木才能正式起跑。
5. 賽後可查看回合、學習主題、完成時間、平均速度、極速、碰撞、事件執行次數、積木修改紀錄及與前回合的比較。記錄學習過程，並非只看名次。

**角色安全**：教師建立房間後取得獨立的高熵隨機權杖。教師管理指令全部在伺服器驗證 Socket 會話；學生不能單靠更改網址進入教師模式。這是課堂權杖驗證，不是學校 SSO。

**短暫斷線重入**：瀏覽器在本機保存房間和角色權杖，重新整理後會嘗試回到原房間。房間資料目前存在單一伺服器程序記憶體中，部署重啟或 Render 休眠後可能消失，不能宣稱跨部署持久保存。

## 技術架構

- 前端：原生 JavaScript、Canvas 2D、Google Blockly 11；16:9、1600×900 固定舞台依螢幕等比例 CSS zoom 縮放，不以窄螢幕改列。
- 後端：Node.js 20+、Express 4、Socket.IO 4，伺服器權威計算物理並同步狀態；房間最多兩位學生加一位旁觀教師。
- 程式解譯：Blockly 積木轉有限 AST，限制積木種類、值域、數量、深度、事件與回合內容，沒有 eval、Function 或任意來源程式碼執行。
- 測試：Node.js 單元／兩個真實 Socket.IO client 整合測試、Playwright 三個獨立瀏覽器情境與不同解析度測試，及 GitHub Actions main 分支自動測試。
- 資料：房間、成績與權杖存在伺服器記憶體；學生端保留會話資訊。沒有持久化 LMS 帳戶或跨多執行個體的 Redis。

## 本機安裝與測試

需 Node.js 20 以上。在專案根目錄執行：

    npm install
    npm start

瀏覽器開啟 http://localhost:3000。再開一個老師與兩個獨立學生分頁，使用同一房間代碼。

單元與多人連線整合測試：

    npm test

三個真實 Chromium 頁面的積木、角色、即時賽車與等比例縮放測試：

    npx playwright install chromium
    npm run test:e2e

健康檢查：GET /api/health，回傳 ok: true、遊戲名稱與現存房間數。

## Render 部署設定

**必須建立 Render Web Service，而非 Static Site**，因為 Socket.IO 需要常駐 Node 伺服器。

| 項目 | 設定 |
| --- | --- |
| GitHub | Chuang-Chih-Hao/2-Player-Coding-Racing-Game |
| Branch | main |
| Runtime | Node |
| Region | Singapore |
| Build Command | npm install |
| Start Command | npm start |
| 自動部署 | main 變更時部署 |
| 環境變數 | NODE_ENV=production（選填） |
| Port | 使用 Render 自動設定的 PORT |
| Health | /api/health |

專案附 render.yaml 作為 Blueprint 設定參考。請以 Render 控制台實際建立、部署結果及公開 /api/health 驗證為準，不能只因 render.yaml 存在就認定部署成功。

Render 免費服務可能休眠；休眠或重新部署會失去記憶體內房間、權杖與報表。若要永久保存學習紀錄、支援多執行個體，後續需加入 Redis／資料庫與真正的持久化身分管理。
